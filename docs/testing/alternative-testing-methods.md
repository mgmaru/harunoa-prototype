# 代替テスト方法の提案（実機なしでのテスト）

本ドキュメントでは、スマートフォン実機が手元にない場合や、複数端末テストを1台のPCで実施するための代替手法について提案します。
`docs/testing/test-scenarios.md` の「9. 複数端末」および「12. レスポンシブ対応」などのテスト実施にご活用ください。

## 1. スマートフォンでのログイン・操作のテスト

PCのブラウザ（Chrome等）の「デベロッパーツール」を使用することで、スマートフォンの画面サイズや挙動をシミュレーションできます。

### Chrome デベロッパーツールの使用方法

1. **デベロッパーツールを開く**
   - 画面上で右クリックし、「検証 (Inspect)」を選択する。
   - または、ショートカットキー `F12` キー（または `Ctrl + Shift + I`）を押す。

2. **デバイスモードに切り替える**
   - デベロッパーツールの左上にある「スマホ・タブレットのアイコン」をクリックする（または `Ctrl + Shift + M`）。
   - ブラウザの表示領域がスマホの形状に変わります。

3. **デバイスを選択する**
   - 画面上部のドロップダウンメニュー（初期表示は「Dimensions: Responsive」等）から、テストしたいデバイス（例: iPhone 12, Pixel 5）を選択します。
   - 画面サイズやタッチイベントがシミュレーションされます。

これにより、「スマホでログイン」「スマホで計測開始ボタンをタップ」といった操作をPC上で実施可能です。

## 2. 複数端末でのテスト（データ同期・競合解決）

1台のPCで「PC」と「スマホ」の2つの役割を同時に演じるには、ブラウザの**シークレットモード（Incognito Window）**や**プロファイル機能**を活用して、セッション（ログイン状態）を分離します。

### 推奨構成: 通常ウィンドウ + シークレットウィンドウ

最も手軽な方法です。

| 役割（仮想） | ブラウザの状態 | 実施方法 |
| :--- | :--- | :--- |
| **端末A (例: PC)** | **通常ウィンドウ** | 普段使っているブラウザ画面。こちらでログインします。 |
| **端末B (例: スマホ)** | **シークレットウィンドウ** | ブラウザメニューから「新しいシークレット ウィンドウ」を開きます。 |

**実施手順例（テストシナリオ 9.1 データ同期）:**

1. **【端末A (PC)】** 通常ウィンドウでアプリを開き、ログインする。
2. **【端末B (スマホ)】** シークレットウィンドウを開き、デベロッパーツールで「スマホ表示」にする。
3. **【端末B (スマホ)】** シークレットウィンドウでもアプリを開き、ログインする。
   - この時点で、論理的に「別の端末」として扱われます。
4. **テスト実行**:
   - 端末Aでプロジェクトを作成する。
   - 端末B（シークレット＆スマホ表示）をリロードまたは操作し、プロジェクトが表示されるか確認する。

### その他の方法

- **複数のブラウザを使用する**:
  - Chrome と Firefox を同時に開き、それぞれでログインする。
- **Chrome プロファイルを使用する**:
  - Chromeの右上のアイコンから「追加」で新しいプロファイルを作成し、別のウィンドウとして開く。

## 3. テストシナリオへの適用ガイド

### 「9. 複数端末」への適用

#### 9.1 データ同期
- **PC役**: 通常のChromeウィンドウ
- **スマホ役**: シークレットウィンドウ + デベロッパーツール（スマホモード）
- これらを左右に並べて配置し、片方の操作がもう片方に反映されるかを確認します。

#### 9.2 競合解決（後勝ち）
- 同様に2つのウィンドウ（通常 vs シークレット）を用意します。
- 両方で「同じ編集画面」を開いた状態にします。
- **端末A**で保存 → **端末B**で保存、の順序で操作し、最終的な結果を確認します。

### 「12. レスポンシブ対応」への適用

- 基本的に「デベロッパーツール（デバイスモード）」のみで検証可能です。
- iPhone SE（小画面）、iPhone 12/Pixel（標準）、iPad（タブレット）などを切り替えて、レイアウト崩れがないかを確認してください。
