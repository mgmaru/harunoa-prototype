# ポモドーロ機能テスト実行ガイド

関連ドキュメント：`test-scenarios.md` 5章

---

## 概要

本ドキュメントは、ポモドーロ機能のテスト項目のうち、**時間経過が必要でSKIPとなっている項目**のテスト実行方法をまとめたものです。

### 対象テスト項目

| テストID | テスト名 | 現在のステータス |
|:--------:|----------|:----------------:|
| 5.5 | ポモドーロの基本サイクル動作 | ⏭️ SKIP (1/3) |
| 5.6 | 休憩スキップ | ⏭️ SKIP (0/3) |
| 5.7 | ポモドーロとセッションの分離確認 | ⏭️ SKIP (2/3) |

---

## SKIPの理由

### 根本原因

ポモドーロのテストには**実際の時間経過**が必要です。

- 集中時間: 最短25分
- 休憩時間: 最短5分
- 合計: **最短30分**

自動テスト（Playwright MCP）で30分の実時間を待機することは非現実的なため、これらのテスト項目はSKIPとなっています。

### テスト項目別の詳細

#### 5.5 ポモドーロの基本サイクル動作

| No | 操作 | ステータス | 理由 |
|:--:|------|:----------:|------|
| 1 | ポモドーロを有効にして計測開始 | ✅ PASS | 即時確認可能 |
| 2 | 集中時間（25分）経過後、休憩フェーズに切り替わる | ⏭️ SKIP | 25分の待機が必要 |
| 3 | 休憩時間（5分）経過後、通知が表示される | ⏭️ SKIP | 追加5分の待機が必要 |

#### 5.6 休憩スキップ

| No | 操作 | ステータス | 理由 |
|:--:|------|:----------:|------|
| 1 | ポモドーロを使用して計測開始 | ⏭️ SKIP | - |
| 2 | 集中時間終了後、休憩画面になる | ⏭️ SKIP | 5.5 No.2に依存 |
| 3 | 「スキップ」をクリック | ⏭️ SKIP | 休憩画面に到達できない |

#### 5.7 ポモドーロとセッションの分離確認

| No | 操作 | ステータス | 理由 |
|:--:|------|:----------:|------|
| 1 | ポモドーロを使用せずに30分計測 | ✅ PASS | 即時停止でセッション作成可 |
| 2 | ポモドーロ（25分+5分）を使用して計測 | ✅ PASS | 計測開始は即時確認可能 |
| 3 | 履歴・集計でポモドーロ時間が含まれないことを確認 | ⏭️ SKIP | サイクル完了が必要 |

### 方法1: テスト用短縮プリセット

**実装ステータス**: 🔧 要実装

#### 概要

テスト環境でのみバリデーションを緩和し、短い集中時間・休憩時間のプリセットを作成できるようにします。

#### 実装方針

```typescript
// src/components/features/presets/PresetFormModal.tsx

// 環境変数でテストモードを判定
const isTestMode = process.env.NEXT_PUBLIC_TEST_MODE === 'true';

// バリデーション値
const MIN_FOCUS_TIME = isTestMode ? 1 : 25;  // テスト時は1分、本番は25分
const MAX_FOCUS_TIME = 60;
const MIN_BREAK_TIME = isTestMode ? 1 : 5;   // テスト時は1分、本番は5分
const MAX_BREAK_TIME = 10;
```

#### テスト実行手順（実装後）

1. 環境変数を設定してアプリを起動
   ```bash
   NEXT_PUBLIC_TEST_MODE=true npm run dev
   ```

2. プリセット管理画面を開く

3. テスト用プリセットを作成
   - 名前: 「テスト用」
   - 集中時間: 1分
   - 休憩時間: 1分

4. 作成したプリセットを「利用中」に設定

5. 計測を開始し、以下を確認
   - 1分後に休憩フェーズへ自動切り替え
   - 休憩中に「スキップ」ボタンが動作
   - 休憩終了後に通知が表示

#### メリット・デメリット

| メリット | デメリット |
|----------|------------|
| 本番コードに近い形でテスト可能 | 実装が必要 |
| CI/CDへの組み込みが容易 | 環境変数の管理が必要 |
| 再現性が高い | - |

#### 既存機能への影響分析

##### バリデーションの実装箇所

| レイヤー | ファイル | バリデーション内容 |
|----------|----------|-------------------|
| フロントエンド | `PresetFormModal.tsx:52-72` | 集中≥25分, 休憩5〜10分 |
| フロントエンド | `PresetFormModal.tsx:145,169` | HTML5 input属性 `min/max` |
| サービス層 | `presets.ts` | **なし**（値をそのまま保存） |
| Firestoreルール | `firestore.rules:133-138` | 集中>0 & ≤120, 休憩>0 & ≤60 |

##### 本番環境への影響

**結論: 影響なし**

環境変数 `NEXT_PUBLIC_TEST_MODE` が未設定（または `false`）の場合：

```typescript
const MIN_FOCUS_TIME = isTestMode ? 1 : 25;  // → 25（既存動作と同一）
const MIN_BREAK_TIME = isTestMode ? 1 : 5;   // → 5（既存動作と同一）
```

##### Firestoreルールとの整合性

**結論: 問題なし**

```javascript
// firestore.rules（133-138行目）
request.resource.data.focusDurationMinutes > 0 && <= 120
request.resource.data.breakDurationMinutes > 0 && <= 60
```

1分の値は `> 0` を満たすため、Firestoreルールをパスします。

##### 注意が必要な点

| 項目 | リスク | 対策 |
|------|:------:|------|
| 環境変数の誤設定 | 中 | 本番デプロイ時に `NEXT_PUBLIC_TEST_MODE` を設定しない |
| HTML5 input属性 | 高 | `min={25}` がハードコードされているため、**同時に変更が必要** |

##### HTML5 input属性の修正（必須）

現在のコード（ハードコード）:
```tsx
<input min={25} max={120} ... />  // 集中時間
<input min={5} max={10} ... />    // 休憩時間
```

テストモードで1分を入力すると、**ブラウザのネイティブバリデーション**でブロックされます。

修正後（動的化）:
```tsx
<input min={MIN_FOCUS_TIME} max={120} ... />  // 集中時間
<input min={MIN_BREAK_TIME} max={10} ... />   // 休憩時間
```

##### 影響分析まとめ

| 質問 | 回答 |
|------|------|
| 本番環境の既存機能に影響があるか？ | **なし**（環境変数を正しく設定すれば） |
| 追加で修正が必要な箇所はあるか？ | **あり**（HTML5 input属性の`min`値を動的化） |
| Firestoreルールの変更は必要か？ | **不要**（既存ルールで1分も許可） |

### 方法2: タイマーモック（Playwright MCP）

**実装ステータス**: ✅ 実行可能

#### 概要

Playwright MCPの`browser_evaluate`を使用して、JavaScriptのタイマー関数をモックし、時間を加速させます。

#### 事前準備

Playwright MCPが利用可能な環境で実行してください。

#### テスト実行手順

**Step 1: アプリにアクセス**

```
browser_navigate: http://localhost:3000
```

**Step 2: ログイン後、タイマーモックを注入**

```javascript
// browser_evaluate で実行
(() => {
  // オリジナルの関数を保存
  const originalSetInterval = window.setInterval;
  const originalSetTimeout = window.setTimeout;

  // 加速倍率（100倍 = 30分が18秒に）
  const SPEED_MULTIPLIER = 100;

  // setIntervalをオーバーライド
  window.setInterval = (callback, delay, ...args) => {
    return originalSetInterval(callback, delay / SPEED_MULTIPLIER, ...args);
  };

  // setTimeoutをオーバーライド
  window.setTimeout = (callback, delay, ...args) => {
    return originalSetTimeout(callback, delay / SPEED_MULTIPLIER, ...args);
  };

  console.log(`[テストモード] タイマー${SPEED_MULTIPLIER}倍速で動作中`);
})();
```

**Step 3: ポモドーロを有効にして計測開始**

1. タイマー画面でプロジェクトを選択
2. ポモドーロをONに設定
3. 「計測開始」をクリック

**Step 4: テスト確認（約18秒後）**

- 集中フェーズ → 休憩フェーズへの自動切り替えを確認
- 休憩中の「スキップ」ボタンをクリック
- 通知の表示を確認

#### 注意事項

- タイマーモックはブラウザのJavaScript環境のみに適用されます
- サーバー側の時刻（Firestoreのタイムスタンプ等）は加速されません
- ページリロードでモックがリセットされます

#### メリット・デメリット

| メリット | デメリット |
|----------|------------|
| コード変更不要 | サーバー時刻との不整合の可能性 |
| 即時実行可能 | ページリロードでリセット |
| 大幅な時間短縮 | モック注入のタイミングに注意 |

### 方法3: デバッグAPI

**実装ステータス**: 🔧 要実装

#### 概要

開発環境でのみ有効なデバッグAPIを追加し、ポモドーロの内部状態を直接操作できるようにします。

#### 実装方針

```typescript
// src/hooks/usePomodoro.ts（または専用のデバッグファイル）

// 開発環境でのみデバッグAPIを公開
if (process.env.NODE_ENV === 'development') {
  (window as any).__DEBUG_POMODORO__ = {
    // 残り時間を設定（秒）
    setRemainingTime: (seconds: number) => {
      // pomodoroState.remainingTime を直接更新
    },

    // フェーズを強制切り替え
    forcePhaseTransition: (phase: 'focus' | 'break') => {
      // pomodoroState.currentPhase を直接更新
    },

    // 現在の状態を取得
    getState: () => {
      return { /* pomodoroState */ };
    },
  };
}
```

#### テスト実行手順（実装後）

**Step 1: 開発サーバーを起動**

```bash
npm run dev
```

**Step 2: ポモドーロを有効にして計測開始**

**Step 3: ブラウザのコンソールでデバッグAPIを呼び出し**

```javascript
// 残り時間を5秒に設定
__DEBUG_POMODORO__.setRemainingTime(5);

// または、強制的に休憩フェーズへ移行
__DEBUG_POMODORO__.forcePhaseTransition('break');
```

**Step 4: 動作を確認**

#### メリット・デメリット

| メリット | デメリット |
|----------|------------|
| 細かい状態制御が可能 | 実装が必要 |
| 任意のシナリオをテスト可能 | 本番環境への漏れに注意 |
| サーバー時刻との不整合がない | - |

### 方法4: 手動テスト

**実装ステータス**: ✅ 実行可能

#### 概要

実際の時間経過を待ってテストを実施します。最も確実な方法です。

#### 事前準備

- ローカル環境（Firebase Emulator + Next.js dev server）を起動
- テスト用のGoogleアカウントでログイン

#### テスト実行手順

##### 5.5 ポモドーロの基本サイクル動作

| 手順 | 操作 | 確認項目 | 所要時間 |
|:----:|------|----------|:--------:|
| 1 | タイマー画面でプロジェクトを選択 | - | - |
| 2 | ポモドーロをONに設定 | トグルがONになる | - |
| 3 | 「計測開始」をクリック | 集中モード画面に遷移、ポモドーロタイマー表示 | - |
| 4 | **25分待機** | 経過時間が増加し続ける | 25分 |
| 5 | 集中時間終了を確認 | 自動で休憩フェーズに切り替わる、通知表示 | - |
| 6 | **5分待機** | 休憩タイマーがカウントダウン | 5分 |
| 7 | 休憩時間終了を確認 | 休憩終了の通知が表示される | - |

**合計所要時間**: 約30分

##### 5.6 休憩スキップ

| 手順 | 操作 | 確認項目 | 所要時間 |
|:----:|------|----------|:--------:|
| 1 | ポモドーロを有効にして計測開始 | 集中フェーズ開始 | - |
| 2 | **25分待機** | - | 25分 |
| 3 | 休憩フェーズに切り替わることを確認 | 休憩中の表示に変わる | - |
| 4 | 「スキップ」ボタンをクリック | 休憩が終了し、次の集中フェーズが開始 | - |

**合計所要時間**: 約25分

##### 5.7 ポモドーロとセッションの分離確認

| 手順 | 操作 | 確認項目 | 所要時間 |
|:----:|------|----------|:--------:|
| 1 | ポモドーロOFFで計測開始 | - | - |
| 2 | 任意の時間後に停止 | セッションが保存される | - |
| 3 | 履歴画面で計測時間を確認 | 実際の経過時間が記録されている | - |
| 4 | ポモドーロONで計測開始 | 集中フェーズ開始 | - |
| 5 | **25分+5分待機**（1サイクル完了） | - | 30分 |
| 6 | 計測を停止 | セッションが保存される | - |
| 7 | 履歴・集計画面を確認 | ポモドーロの集中・休憩時間はプロジェクトの作業時間に**含まれない** | - |

**合計所要時間**: 約35分

## 推奨アプローチ

### 開発フェーズ別の推奨方法

| フェーズ | 推奨方法 | 理由 |
|----------|----------|------|
| 日常的な開発 | 方法2（タイマーモック） | 即時実行可能、コード変更不要 |
| CI/CD自動テスト | 方法1（短縮プリセット） | 実装後は安定して自動実行可能 |
| リリース前確認 | 方法4（手動テスト） | 本番相当の条件で最終確認 |
| デバッグ・調査 | 方法3（デバッグAPI） | 任意の状態を再現可能 |

### 実装優先度

1. **方法1（短縮プリセット）** - CI/CDでの自動テストに最も適している
2. **方法3（デバッグAPI）** - 開発時のデバッグ効率向上
