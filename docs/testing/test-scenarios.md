# 受け入れテストシナリオ（HaruNoa）

関連ドキュメント：requirements.md 11節

---

## 概要

本ドキュメントは、HaruNoa v2（MVP）の受け入れテストシナリオを定義する。
要件定義書の「受け入れ条件」に基づいて作成。

### テストシナリオ数

| カテゴリ | テスト数 |
|----------|:--------:|
| 1. プロジェクト管理 | 8 |
| 2. 計測機能 | 6 |
| 3. 履歴管理 | 11 |
| 4. 集計・グラフ | 4 |
| 5. ポモドーロ | 9 |
| 6. 通知 | 5 |
| 7. データ管理 | 4 |
| 8. 認証 | 5 |
| 9. 複数端末 | 2 |
| 10. オフライン対応 | 4 |
| 11. 非機能要件 | 2 |
| 12. レスポンシブ対応 | 2 |
| **合計** | **62** |

### 実施環境の凡例

| 記号 | 環境 | 説明 |
|:----:|------|------|
| L | ローカル | Firebase Emulator + Next.js dev server |
| S | ステージング | 本番相当環境（Vercel Preview等） |
| P | 本番 | スモークテスト（主要フローのみ） |

### 環境別の実施方針

| 環境 | 実施範囲 | 目的 |
|------|----------|------|
| ローカル | 1〜8章（機能テスト） | 機能が正しく動作するか確認 |
| ステージング | 全62項目 | 本番相当環境での動作確認＋環境依存テスト |
| 本番 | 主要フローのみ（15〜20項目） | デプロイ後の疎通確認 |

### 発見した問題

#### 1. Firestoreルールとコレクション名の不一致

- **現象**: `Failed to ensure default preset: FirebaseError` エラーが頻発
- **原因**: firestore.rulesでは `presets` コレクションを定義しているが、src/services/presets.tsでは `pomodoroPresets` コレクションを使用
- **影響**: ポモドーロプリセット機能が動作しない
- **対応**: firestore.rulesまたはサービスコードの修正が必要

#### 2. プロジェクト名重複時の警告未表示 ✅ 修正済み

- **現象**: 同名プロジェクト作成時に警告が表示されない
- **期待動作**: テストシナリオ1.8では「警告表示されるが作成可能」
- **実際の動作**: 警告なしで作成される
- **影響**: 軽微（作成自体は可能）
- **対応**: ✅ `ProjectCreateModal.tsx`に`existingNames`プロップと`isDuplicate`判定を追加。入力名が既存名と一致する場合に警告メッセージを表示

#### 3. プロジェクト一覧の合計時間・最終計測日が更新されない ✅ 修正済み

- **現象**: 計測後もプロジェクト一覧で「合計: 0分」「最終計測: -」のまま
- **期待動作**: 計測完了後に合計時間と最終計測日が更新される
- **実際の動作**: 履歴画面ではセッションが表示されるが、プロジェクト一覧には反映されない
- **影響**: 中程度（ユーザーが作業時間を一覧で確認できない）
- **対応**: ✅ `useProjectStats.ts`フックを新規作成。期間別（日/週/月）にセッションを取得し、プロジェクトごとの合計時間と最終計測日を集計。`page.tsx`と`ProjectList.tsx`に統計情報の受け渡しを追加

#### 4. アーカイブ済みプロジェクトの集計除外が機能していない ✅ 確認済み

- **現象**: プロジェクトをアーカイブしても集計画面にデータが表示される
- **期待動作**: アーカイブ済みプロジェクトのセッションは集計に含めない
- **実際の動作**: アーカイブ後も集計画面で合計時間に含まれる
- **影響**: 中程度（アーカイブの意味が薄れる）
- **対応**: ✅ 既に`aggregation.ts:104-106`で`if (!project || project.isArchived) continue;`としてアーカイブ除外ロジックが実装済み。1回目テスト時はページ再読み込みせずに確認したため反映されていなかった。2回目テストで正常動作を確認

#### 5. 日付跨ぎセッションの按分が翌日の集計に反映されない ✅ 修正済み

- **現象**: 日付を跨ぐセッション（例: 23:50〜00:10）の翌日分が集計に含まれない
- **期待動作**: 前日に10分、翌日に10分が按分されて計上される
- **実際の動作**: 前日には10分が計上されるが、翌日の集計には0分
- **原因**: `src/services/sessions.ts`の`getSessionsByPeriod`関数が`startAt`フィールドのみでフィルタリングしているため、開始日が異なる日のクエリには含まれない
- **影響**: 中程度（日付跨ぎセッションの正確な按分ができない）
- **対応**: ✅ `getSessionsByPeriod`関数を修正。2つのクエリ（`startAt`が期間内 + `endAt`が期間内）を並列実行してマージし、日付跨ぎセッションも正しく取得できるように変更

#### 6. 複数日跨ぎセッション（48時間以上）が中間日の集計に含まれない ✅ 修正済み

- **現象**: 48時間セッション（例: 1/1 10:00〜1/3 10:00）の中間日（1/2）で集計すると0時間になる
- **期待動作**: 1/1=14時間、1/2=24時間、1/3=10時間と按分される
- **実際の動作**: 1/1=14時間、1/2=0時間、1/3=10時間（中間日が取得されない）
- **原因**: `getSessionsByPeriod`関数が「期間を完全に跨ぐセッション」（startAt < periodStart かつ endAt > periodEnd）を取得できていない
- **影響**: 中程度（複数日跨ぎセッションの按分が不正確）
- **対応**: ✅ `getSessionsByPeriod`関数に3つ目のクエリを追加。期間開始日の30日前〜期間開始日より前に開始したセッションを取得し、endAt > periodEndのものを期間を跨ぐセッションとしてマージ

#### 7. 計測時間の直接入力機能が未実装 ✅ 修正済み

- **現象**: セッション編集モーダルで計測時間の入力フィールドがなく、表示のみ
- **期待動作**: 計測時間を直接入力すると、終了時刻が自動計算される（要件定義書 4.4.2）
- **実際の動作**: 計測時間は開始/終了時刻から自動計算されるだけで、入力できない
- **原因**: `SessionEditModal.tsx`で計測時間が表示専用として実装されていた
- **影響**: 中程度（ユーザーが計測時間を直接補正できない）
- **対応**: ✅ `SessionEditModal.tsx`に計測時間入力フィールド（時間・分）を追加。時間/分の入力値変更時に終了時刻を自動計算。開始時刻変更時は計測時間を維持して終了時刻を再計算。0分入力時のバリデーションも追加

#### 8. プロジェクトフィルタ機能が未実装 ✅ 修正済み

- **現象**: 履歴画面にプロジェクトフィルタのUIがなく、全プロジェクトのセッションのみ表示される

- **実際の動作**: プロジェクトフィルタUIが存在しない
- **原因**: 画面仕様書・実装指示書にプロジェクトフィルタの記載がなく、実装されていなかった
- **影響**: 中程度（ユーザーが特定プロジェクトの履歴を絞り込めない）

  - `src/services/sessions.ts`: `getSessionsByDate`関数に`projectId`オプションを追加

#### 9. ページネーション機能が未実装 ✅ 修正済み

- **現象**: 履歴画面にページネーションUIがなく、全セッションが一度に表示される
- **期待動作**: 1ページあたり50件表示し、次へ/前へボタンでページ移動できる（要件定義書 5.4.1）

#### 12. 利用中プリセット削除時の警告ダイアログが未実装 ✅ 修正済み

- **現象**: 利用中のプリセットを削除しようとすると、削除ボタンが無効化されているためクリックできない
- **期待動作**: 警告ダイアログが表示され、削除を確定するとデフォルトプリセットが利用中になる（テストシナリオ 5.9、画面仕様書 4.7 No.5）
- **原因**: `PresetCard.tsx`で`preset.isActive`の場合に削除ボタンを無効化している実装
- **影響**: 軽微（利用中プリセットの誤削除は防止されている）
- **対応**: ✅ 以下の4ファイルを修正
  - `src/components/features/presets/PresetCard.tsx`: 利用中プリセット（非デフォルト）の削除ボタンを有効化。削除不可条件を`!isDefault`に変更
  - `src/components/features/presets/PresetDeleteModal.tsx`: `isActive`プロップを追加し、利用中プリセット削除時に警告メッセージ「⚠️ このプリセットは現在利用中です。削除すると「デフォルト」プリセットが自動的に利用中になります。」を表示
  - `src/services/presets.ts`: `deleteActivePresetAndSetDefault`関数を追加。利用中プリセット削除時にデフォルトプリセットを自動でアクティブに設定
  - `src/hooks/usePresets.ts`: `remove`関数を修正。利用中プリセット削除時は`deleteActivePresetAndSetDefault`を使用

#### 13. ポモドーロ開始時にstartWithTimerが古い状態を参照する ✅ 修正済み

- **現象**: 計測開始時にポモドーロの集中フェーズが開始されない（プログレスバーが表示されない）
- **期待動作**: ポモドーロプリセット選択後に計測を開始すると、集中フェーズが開始される
- **原因**: `usePomodoro.ts`の`startWithTimer`関数が`useCallback`で作成されているが、`useTimer.ts`の`handleStart`の依存配列が空`[]`のため、古い`startWithTimer`（`isEnabled: false`の時点の関数）がキャプチャされたまま使用されていた
- **影響**: 高（ポモドーロ機能が動作しない）
- **対応**: ✅ `src/hooks/usePomodoro.ts`の`startWithTimer`関数を修正。`usePomodoroStore.getState()`を使用してZustandストアから直接最新の状態を取得するように変更

#### 14. 休憩スキップが次の集中フェーズを開始しない ✅ 修正済み

- **現象**: 休憩中にスキップボタンをクリックすると、ポモドーロが停止（idle）して通常の計測モードに戻る
- **期待動作**: スキップ後に次の集中フェーズが開始される（テストシナリオ 5.6 No.3）
- **原因**: `pomodoroStore.ts`の`skipBreak`関数が`phase: 'idle'`を設定しており、次の集中フェーズを開始していなかった
- **影響**: 中程度（休憩スキップ後にポモドーロサイクルが途切れる）
- **対応**: ✅ `src/stores/pomodoroStore.ts`の`skipBreak`関数を修正。`phase: 'focus'`と`remainingMs: focusDurationMinutes * 60 * 1000`を設定して次の集中フェーズを開始するように変更

#### 15. Firestoreルールとコレクション名の不一致（userSettings） ✅ 修正済み

- **現象**: 設定画面で「Failed to fetch settings: FirebaseError: false for 'get' @ L152」エラーが発生
- **期待動作**: 設定画面が正常に読み込まれ、通知設定のトグルが操作可能
- **原因**: `firestore.rules`では`settings`コレクションを定義しているが、`src/services/settings.ts`では`userSettings`コレクション（`USER_SETTINGS_COLLECTION = 'userSettings'`）を使用
- **影響**: 高（通知設定画面が動作しない）
- **対応**: ✅ `firestore.rules`に`userSettings`コレクションのルールを追加
