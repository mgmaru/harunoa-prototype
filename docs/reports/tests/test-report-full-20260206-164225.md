## 失敗パターン分析

### パターン1: セッション取得失敗（空配列）

**失敗テスト**: 2件

- INT-005: 計測停止後、セッションが保存され履歴画面で確認できる
- INT-011: 履歴画面でセッション削除後、リストから除外される

**共通点**: セッション取得時に空配列が返される。

**推定原因**:

- モックされた`fetchSessions`が正しく動作していない
- テスト環境でのデータ永続化が機能していない
- タイミング問題（非同期処理の待機不足）

### パターン2: セッションオブジェクトがundefined

**失敗テスト**: 2件

- INT-005: セッションの開始時刻、終了時刻、作業時間が正しく保存される
- INT-011: useSessionsのrefreshで最新データが取得できる

**共通点**: セッションオブジェクトが`undefined`。

**推定原因**:

- セッションが取得できていない（パターン1の派生）
- 配列のインデックスアクセスで要素が存在しない
